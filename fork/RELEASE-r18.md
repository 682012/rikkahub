# RikkaHub 3.1.1-r18 · 发送清理、可靠队列与断线恢复

基于正式 r17 累加，版本 `3.1.1-r18 / 3000065`，包名 `me.rerere.rikkahub.fork` 与正式签名保持，可按常规覆盖升级。r17 的中文、六角色本名、多图设置及既有功能不回退；历史标签与资产保留。

## 发出去的内容不再占输入框

此前的清理回执要等消息写进聊天记录。AI 正忙时，新消息只进入等待队列，回执迟迟不完成，输入就一直留着。

r18 把回执改为“可靠入队确认”：先将消息写进会话独立的待发文件，确认成功就清掉已提交内容，不等前一轮回复结束。等待这一下确认时追加的新文字和附件保留，光标随剩余文字移动；写盘或初始化失败则保留原稿，不假装发送成功。

## 待发送消息有可靠归属

- 每个会话一份私有队列，临时文件写入、fsync 后原子替换，成功才更新内存和受理回执。
- 发送前恢复旧队列，不把未打开会话里的消息覆盖掉。原助手归属保留，不能把 A 的待发内容交给 B。
- 出队到聊天数据库提交之间保留 `inFlight`；用同一个消息 UUID 写入历史，恢复时不重复添加。数据库提交后才确认移出队列。
- 重启可找回尚未写入历史的待发输入。中途被打断的队列编辑保留原内容并暂停，用户确认后再继续，不偷偷把旧稿发送出去。
- 队列损坏或磁盘写入失败明确报错，保留原文件和输入，不把坏文件当空队列覆盖。处理完的空队列不留文件。

## 网络恢复后真正继续

此前网络回调只唤醒正在等待的请求；生成已经失败、队列已暂停后，回调没有继续接回它们。

r18 给网络暂停、手动停止和普通错误分别记原因。网络恢复或路由切换时，先恢复原来失败的文字轮次，再按顺序处理待发送消息，不要求对应会话页开着。原会话、用户消息或分支已经变化时，旧恢复任务作废。

恢复使用已完成模型步骤的检查点，保留工具执行结果，不把半截新输出反复追加。已经开始而结果不明的工具不会自动重放，待审批不会被网络事件绕过；工具和图片生成不作为网络恢复任务重复执行。

等待重试期间再次掉线，会用本次剩余预算等恢复；离线等待、被换网作废和普通失败分开记账。普通重试仍遵守设置中的次数和等待时间，关闭自动重试或设为 0 不会被后台恢复绕过。手动停止后不会因来网而复活；用户主动新发消息或点继续才恢复对应队列。

## 验证范围与边界

仅运行本次发送策略、可靠队列/真实文件存储、恢复检查点、重试预算与网络等待的定向 Kotlin/JUnit 检查。实际数字与源码哈希随 Release 的 `TARGETED-VALIDATION.json` 提供，不把 r17 的结果当本轮测试。

正式包使用 Windows 云节点 `release`（R8 + lintVital），版本、原签名、双 ABI、CRC、中文资源、原图和人设资源、源码归档与公开下载分别核对。

未自动安装手机，未做真机界面或真实供应商的断网实测。网络恢复依赖 Android 网络回调和进程仍能运行；新队列的持久化不能补回旧版从未落盘的队列，也不等于可以跨进程接回已经断开的远端 TCP 连接。已开始的远端副作用不自动重放。
