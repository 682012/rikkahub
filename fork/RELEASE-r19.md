# RikkaHub 3.1.1-r19 · 图片并发、语音调节与 TTS 提速

基于正式 r18 累加，版本 `3.1.1-r19 / 3000066`，包名、签名、应用名与图标不变，可直接覆盖本分支旧版。保留 r18 可靠队列与重连、r17 中文/角色本名/多图规则，不修改历史标签和安装包。

## 图片整理并发

入口「设置 → 图片整理」，在识别模型下面调整「图片整理并发数」。默认 3 路，可选 1–16 路，选择写入应用私有文件，重开页面和重启后保留；识别期间锁定本批设置。实际请求仍受所选模型的共享并发上限约束。

用固定数量工作协程逐张取图，不为所有图片同时创建请求或解码大图。图片仍先采样、缩图后识别；本地分类缓存继续复用，单张失败不打断其他图片，取消后保留完成项。并发不会减少总识别次数，不保证线性提速；上游限流、网速和模型响应会影响收益。调高并发会增加内存与上游瞬时压力。这里和聊天「多图发送每批张数」是两个独立功能，后者仍按原规则顺序处理。

## 语言与自由调节

入口「设置 → 语音 → 文本转语音 → 语音调节」：

- 朗读语言可选自动、中文（中国/台湾/香港）、英语（美/英）、日语、韩语、法语、德语、西语、意语、葡语、俄语、阿语、印地语、越南语、泰语、印尼语。
- 语速 0.25–3 倍、音高 0.5–2 倍、音量 0–100%，保存后可沿用；不改手机系统音量。云端音色仍在各提供商中自由选择或输入 ID。
- 编辑「系统 TTS」可单独选语言和本机已安装的音色；单独语言优先于全局。没有对应语言包会明确报错，不静默换成其他语言。原系统合成语速/音高设置保留，会和全局播放调节共同作用。
- OpenAI 配置增加语气与表达指令，发送给 `gpt-4o-mini-tts` 系列；`tts-1` / `tts-1-hd` 不发送不支持的字段。原音色保留，并补全快捷音色选项，仍可手输其他 ID。
- 高级设置可调每段 40–400 字符、提前合成 0–4 段，也能恢复默认。短段能更早开口，但会增加请求数、可能影响语气连贯；预取能缩短段间等待，中途停止时已提交的请求仍可能计费。

语言指定接入系统 TTS、xAI、ElevenLabs 和 `gpt-4o-mini-tts` 支持的字段/指令；其他引擎继续按文本或模型识别语言，不给不支持的接口硬塞参数。选择语言只控制朗读，不翻译原文，也不为只支持单一语言的模型增加语言能力。实际可用语言和音色由当前引擎/模型决定。

## TTS 链路优化

当前段先安排合成，后面的段落才预取；首段最多 80 字符，不再等整段长文本。移除每段固定 120 毫秒等待，已播放音频及时从缓存移除；预取窗口有上限，系统 TTS 串行并复用已初始化的引擎。

OpenAI、Gemini、ElevenLabs、Fish Audio 和 xAI 的普通音频请求共用可取消的 HTTP 读取路径；停止、清空或切换时取消在途请求，关闭响应，单段音频限制 32 MiB。播放侧补了合成等待中暂停、旧播放任务迟到回调隔离和释放资源的处理。

仍是按文本段收齐音频后播放，不宣称所有供应商都做到了音频字节流边收边播。这里只优化客户端，不改远端 Fish 服务或其他服务器，也不保证上游首包时间。短段可能增加供应商最低计费带来的费用。

## 生图空占位清理

修复 `StreamChunkHandler.ImageStart` 只创建空 data URL、随后失败却一直留坏图的问题。`ImageEnd` 与 `Finish` 清理空图片，并同步重排交错文本/推理/其他图片的索引；流直接 EOF 时也会收尾。失败或手动取消经过会话的不可取消收尾，清理后再落库。

打开旧会话时，同样清掉并保存助手消息中遗留的空图片；发给模型的历史副本也先过滤这类占位。只认 `data:image/…` 中没有实际数据的图片，不测试远程链接、不删除用户附件、不动已有图片数据、正文或工具结果。非空但损坏的图片数据不做猜测式删除。

## 验证边界

只运行本次改动的定向 Kotlin/JUnit 检查及正式 `release` 构建（R8 + lintVital），不重跑历史全套。测试数量、冻结提交、sourceId、APK 版本/签名/资源与公开下载哈希以随 Release 的回执为准。

未自动安装手机，未做真机界面点验或真实供应商首声延迟、音质、费用对照。语言与音色在不同系统 TTS 引擎和模型上的实际听感仍需设备实用验证。
