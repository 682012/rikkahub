## 已修复

| 问题 | 原因与影响 | 本轮处理 |
|---|---|---|
| “增量保存”实际全量重写 | `updateConversation` 先删光节点，后面的差分查询只能看到空表；流式落库反复重写长会话 | 去掉预先全删，保留同一事务；差分计算抽出并测试新增、删除、重排、分支切换和流式内容变化 |
| ZIP 导出遍历排除目录、跟随链接 | `walkTopDown` 在文件层才过滤；可走进链接目录、树外内容或循环路径 | 真实 JVM 导出器按目录剪枝，不跟随符号链接，跳过特殊文件及 `.jobs`；扫描和逐块复制响应取消 |
| 导出失败可能显示成功 | SAF 返回 null 输出流时原代码仍显示“导出完成” | 输出流为空即失败；读写错误明确上报；取消时说明目标文件可能不完整 |
| 导出工作区选错 | 页面写“当前工作区”，实际固定 `firstOrNull()` | 按工作区名称选择，文件选择器往返保存选中的 ID，不依赖返回时列表顺序 |
| 子代理忽略网络重试设置 | 固定 `RetryPolicy.NETWORK`，关闭重试仍按旧策略运行 | 与主对话共用 `Settings.retryPolicy()`；回归关闭、次数、取消与实际重试次数 |
| 子代理超长工具输出未走父侧保护 | childTools 在输出外置包装之前构造 | 仅在有本地工作区且子代理确实持有读取工具时外置；无工作区、远程工作区、禁止工作区时保留原文 |
| 远程 HTTP 超时 0 被改成 30 秒 | `takeIf { it > 0 } ?: 30` 与“不限”语义相反 | 0 关闭 call/read/write 超时，保留连接超时；负数明确拒绝；命令总预算仍独立生效 |
| 重试次数显示与保存不一致 | 输入 999 显示 999，实际存 100 | 显示和保存使用同一个收敛值；允许清空重输，失焦恢复已保存值 |
| 旧测试、注释与实现冲突 | 技能描述测试仍期待 1024，现版主动预览 512；压缩注释仍说必须带工具 | 修正测试和注释，不改变技能正文加载、不恢复压缩工具定义 |

导出仍是**文件区 ZIP**，不包含 Rootfs，不保留 Unix 权限或符号链接；缓存/构建目录被排除。文件区内可能包含私钥或其他私密文件，不能公开分享。运行中的文件不是原子快照，重要备份应先停止会改写文件的任务。

## 未采纳的建议

- 不把跨助手历史检索一律收窄：这会改变现有使用范围，不能仅凭另一接口的范围不同就认定泄漏。
- 不从会话用量里剔除标题、压缩、翻译费用：真实发生的费用不能为了口径好看而隐藏。
- 不把模型可指定的步数/时长默认值改成新硬上限：需要明确的预算产品语义，而非借修 bug 加限制。
- 不采用前台服务全局计数重构：初版建议有 acquire/release 竞态，且“后台 release 必然被拒绝”没有真机证据。
- 不采用监视失败后直接释放保活的补丁：读不到元数据不等于进程已停止。

## 仍待处理与真机验收

1. 消息分页、嵌套子代理、独立 token/费用预算仍未实现。`allowNested` 不是可用功能。
2. 子代理 `includeSearch` 有执行判定但没有设置页入口；不会因此获得独立搜索能力。
3. 远程任务列表仍读取本地记录，设置页不等于远程任务管理面板。
4. 自动网络重试主要处理 IOException，不等于自动重试所有 429/5xx；标题/翻译等辅助请求也非全部走同一 Agent 重试链。
5. 真机检查：选择第二个工作区导出；取消大文件导出；SAF 写失败；压缩后保留本轮输入；子代理关闭重试；锁屏 job 与取消；大量聊天持续落库。
6. 本轮不宣称修完全部 bug，也不把 JVM 测试通过当作 Android 真机验收。
