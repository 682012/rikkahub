# 工作区访问权限与目录挂载

入口：**扩展 → 工作区 → 选择本地工作区 → 基本 → 访问权限与挂载**。不影响已有 SSH 工作区。

## 两个执行环境，不混用身份和路径

- **Linux 工作区**：沿用已有 PRoot。`/workspace` 是工作区文件，新增目录可映射到 `/mnt/phone` 等位置。PRoot 显示的 `root` 不代表 Android 系统 Root。
- **Android 宿主命令**：独立的 `workspace_android_shell` 工具和小型命令控制台。使用 Android 的真实绝对路径，不能把 Linux 的 `/workspace` 当成宿主路径。这个入口不要求安装 Linux Rootfs。

APK 不内置 Node、官方 AI CLI、su、Magisk 或 Shizuku 服务端，不另装浏览器内核。Shizuku 客户端 API 是小型 Java 依赖，用户服务按需启动、空闲释放。

## 主动授权

1. **App**：原生 Android shell，以 App 自身 UID 执行。
2. **Shizuku**：用户先安装并启动自己的 Shizuku/Sui，再在本工作区点击授权。返回实际 UID：ADB 启动通常为 2000，Root 启动可以为 0，不把两者混写。
3. **Root**：仅调用设备上用户已有的 `su`，由 Root 管理器决定是否允许；确认真实 UID 0 后才保存本工作区的选择。设备没有 Root，安装本应用也不会获得 Root。

点击已选中的模式仍可重新授权。普通执行不会自动弹出新的 Shizuku 授权请求，不会因为一条通道失败而偷偷换身份。Root 在 App 重启后需主动重新确认。每次结果报告入口身份与 UID；命令自己启动的其他程序可能使用不同身份。

授权记录保存在本机 `noBackup` 目录，不随工作区 ZIP、聊天或设置备份迁移。撤销会禁用该工作区的 Android 执行入口，并取消受管命令。全局 Shizuku/Root 授权仍由各自的管理器控制。任意 shell 和 Root 都不是对抗同 UID 代码的强安全沙箱，不能把工作区设置理解成内核权限隔离。

## 手机目录挂载

- 现代 Android 先点击共享存储授权，进入系统“所有文件访问权限”，由用户开启。普通 SAF 目录授权并不等于 POSIX 文件访问，不能把 `content://` 假装成路径。
- 可选本地存储目录，或填写可访问的 Android 绝对路径和 Rootfs 挂载点。云盘、虚拟 DocumentsProvider 不能直接绑定，需用导入功能。
- 用户目录的映射同时用于命令、交互终端、后台任务和文件工具；按工作区保存，不串到其他工作区。
- 映射改变后关闭本工作区已有的 Linux 终端与受管后台任务，新进程使用新映射。移除映射不删除原目录或其中的文件。
- 这是 **PRoot 路径映射**，不是内核 `mount`。不伪造只读隔离；能否写入仍由源目录的 Android 权限决定。应用内部映射、内核伪文件系统和受管临时目录不能被覆盖。
- 存储授权撤回、卷被拔出或目录消失时明确报错，需要恢复授权或移除此映射，不把空目录冒充已挂载。

## 信任与确认

“信任 Linux 工作区”只减少 Rootfs 文件写入的额外确认，不赋予 Android Root。工具确认仍可按工作区分别设置，Android 命令默认需要确认，用户可自行关闭。不对任意命令做虚假的“安全命令”判断。

## 边界与验证

Shizuku 不会让普通手机变成 Root，也不能凭 UID 2000 读取其他 App 的私有数据；系统 SELinux 和内核能力仍可能拒绝操作。自行执行真实 Root mount 或启动脱离管理的进程，应自行收尾，应用不能承诺回收所有任意 Root 后代进程。

实际测试范围、设备版本、失败/跳过项、APK 签名与哈希，以此版本的验收记录为准。不把单元测试、模拟身份或“存在设置入口”当成真机提权成功。
