# 与原版的差异 / Differences from upstream

基线：RikkaHub `3.0.0`（commit `55a108a4`）
本文件只记录**用户可感知的功能与行为差异**，实现细节见 `fork/README.md`。

---

## 一、新增功能

### 1. 子代理系统

官方 3.0.0 没有子代理，所有任务都在主对话里串行完成。本改版新增：

- 工具：`subagent_run` / `subagent_wait` / `subagent_result` / `subagent_list` / `subagent_cancel`
- 每个子代理有独立模型、独立上下文、独立工具集，结果写文件后只把摘要回传主对话
- 并发上限可配（1–4，默认 2），超出的任务排队
- 主模型失败时可用 fallback 模型重试一次
- 子代理可以读取其他会话：`recent_chats` / `conversation_search` / `conversation_read`
- 运行期间持有前台服务，降低被系统回收的概率
- 设置页可查看任务状态、耗时、错误，并可取消
- 子代理的 token 用量单独记入统计（`source=subagent`）

### 2. 工作区长任务

官方的工作区命令超时是硬编码的：默认 30 秒、上限 600 秒，到点直接杀进程。

本改版：

- 默认超时与最大超时都可配置，填 `0` 表示不限制
- 新增 `workspace_job_start` / `workspace_job_status` / `workspace_job_kill`
  - 进程用 `setsid` 脱离当前 shell，工具返回后继续运行
  - pid 与日志落在工作区 `.jobs/<id>/`，App 重启后仍可查
- 本地任务由前台服务（`specialUse` + partial wakelock）保活，任务结束自动释放
- 日志只读尾部 256KB，不会因为日志过大把内存吃满

### 3. 远程执行后端

官方只能在手机本地 proot 里跑命令。本改版增加了远程后端：

- `POST /exec` 同步执行，`/job/start`、`/job/status`、`/job/kill` 后台任务
- Bearer token 鉴权，服务端脚本见 `fork/rk-exec-server.py`
- 开启后 `workspace_shell` 与 `workspace_job_*` 全部走远程，不受 Android 后台限制
- 适合编译、下载、长时间脚本

### 4. 单会话用量统计

官方只在消息里保留 usage，没有按会话聚合的入口。

本改版：

- 新增 `usage_record` 表（schema 31），每次请求写一条
- 聊天页顶栏“用量”按钮，显示请求数、输入/输出/缓存/合计 tokens、缓存命中率、按模型拆分
- 主对话与子代理分开标记

### 5. 自动上下文压缩

官方 3.0.0 把自动压缩删了，只剩手动“压缩对话”。

本改版恢复自动触发：

- 达到模型 `contextLength` 的阈值（默认 80%）时，先插入一条摘要检查点再继续
- **不删除历史消息**，原始内容仍保留
- 压缩失败不阻塞发送
- 设置页可开关、可调阈值

### 6. 大会话加载优化

官方打开会话会把所有消息节点一次性解析进内存，几十 MB 的会话容易 OOM。

本改版在加载时把大块内容外置到 `filesDir/msg_cache`：

- 内联 base64 图片/视频/音频/文档 → 写成文件，消息里换成 `file://`，显示不变
- 超长工具输出 → 写成 `.txt`，消息里保留 2k 预览 + 文件路径
- 正文不截断，避免影响模型上下文
- 按内容 MD5 去重，7 天或 300MB 自动清理

### 7. 备份兼容性

官方的备份导入只接受能走 Room 迁移的库，遇到“版本相同但分支不同”会直接报 identity hash 不匹配。

本改版在导入的 staging 阶段自动对齐：

- 删除目标结构里不存在的表（例如 excp 分支的 `agent_runs`、`workflows`、`ssh_hosts`）
- 补齐缺失的表和列
- 旧 `MemoryEntity` 先转成 `profile` 记忆文件再删表
- 写入当前 App 的 identity hash
- 对齐后再校验一次，缺表缺列直接报错，不带着残缺结构继续

### 8. 记忆可回退

迁移 27→28 时额外写一份 `_legacy/raw_memories.md`，保留原始条目。官方只生成 `profile`，旧表删除后无法回看。

## 二、与官方不同的行为

| 项目 | 官方 3.0.0 | 本改版 |
|---|---|---|
| 包名 | `me.rerere.rikkahub` | `me.rerere.rikkahub.fork` |
| 版本号 | `3.0.0` / `192` | `3.0.0-fork.N` / `3000000+N` |
| 签名 | 官方密钥 | 自建固定密钥，不能覆盖官方包 |
| 工作区超时 | 默认 30s、上限 600s | 可配，0 = 不限 |
| 子代理 | 无 | 有，工具列表会多出 5 个工具 |
| 自动压缩 | 无（仅手动） | 有，默认 80% 触发 |
| 远程执行 | 无 | 有，可在设置里切换 |
| 用量入口 | 无会话级聚合 | 聊天页顶栏“用量” |
| 消息加载 | 全量解析 | 大块内容外置，部分历史显示为预览 + 路径 |
| 备份导入 | 仅支持可迁移的库 | 额外支持同版本不同分支的结构对齐 |
| 记忆迁移 | 生成 `profile` 后删旧表 | 额外保留 `_legacy/raw_memories.md` |

### 需要注意的行为变化

1. **子代理工具会进入工具列表**。启用后模型能看到 `subagent_*`，部分模型可能误用；不需要时在设置里关掉。
2. **自动压缩会产生额外请求**。达到阈值时会先发一次摘要请求，消耗一次上下文 token；摘要完成前发送会稍慢。
3. **大会话的旧工具输出不再完整显示**。超过 48k 字符的部分变成前 2k + 文件路径，原文在 `msg_cache` 里。
4. **备份对齐会删除其他分支的表**。`excp` 分支的 agent/workflow/ssh/telegram 数据不会进入本改版，原备份不受影响。
5. **不能覆盖安装官方版本**。包名与签名都不同，只能共存；从官方迁移需要导出备份再导入。
6. **远程执行等于把 shell 交给 App**。token 泄露即可在服务器上执行任意命令，不要分享地址和 token。

## 三、内部修复与加固

这些不改变使用方式，但影响稳定性：

- 子代理并发从轮询改成释放信号唤醒
- 子代理任务登记改为先登记再启动，避免 map 泄漏
- 工作区任务日志改为尾部随机读
- 上传超过 128MB（图片 32MB）会提示并跳过，不再静默
- 大图上传时自动采样压缩（长边 4096、质量 85）
- `msg_cache` 定期清理
- 备份对齐后做结构校验
- Room schema 30→31，新增 `usage_record` 表

---

## 四、已知限制

- 用量从写入该表之后开始统计，历史消息不补记
- 自动压缩依赖模型设置里的 `contextLength` 准确，默认 100 万会让阈值形同虚设
- 消息分页尚未实现，超大会话靠外置缓解
- `SubagentTask.steps` 实际记录的是工具调用次数，不是模型步数
- 远程服务端没有多租户隔离，所有任务共享同一个执行目录
