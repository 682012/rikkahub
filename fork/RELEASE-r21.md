# RikkaHub 3.1.1-r21 · 后台任务与分享可靠性修复

基于正式 r20（`5eb8881`）累加生产力分支的最终补丁 `f3171278`，版本 `3.1.1-r21 / 3000068`。原包名、签名、应用名、图标、六只角色原图与完整人设不变；保留 r20 的全部既有功能，不替换 r20 标签或资产。本分支旧版可覆盖升级，升级前请备份聊天与设置，不要先卸载。

## 后台图片整理

- 页面与通知的取消绑定具体任务 ID，旧通知不能取消后来新建的任务。取消状态写入队列存储，进程恢复时不会把已取消批次当作等待执行。
- 自动批次带独立归属。关闭自动整理时停止所属自动任务，不误停手动批次；扫描期间关闭开关也会在入队前重新检查。
- 前台服务启动失败、后台执行失败和系统中断分别处理，更新错误或暂停状态，不让界面一直卡在“排队”。可恢复的未执行内容保留手动继续入口。
- 无法读取的旧队列先持久关闭自动整理，再隔离损坏文件，保留排查材料。不会因恢复失败而自动重新上传图片。
- 不确定已发送结果的请求不自动重放，不以重试掩盖可能重复计费。

## 分享文字与附件

- 大段分享文字保存在应用私有文件中，导航只携带随机 UUID，避免全文进入导航保存状态。
- 保留完整文字，单份上限 4 MiB、待处理总量上限 32 MiB/128 份，过期缓存按 7 天清理。超过限制或读取失败明确提示，不静默截断；可改为分享文本文件。
- 读取与写入放到 IO 线程，导入失败可重试；保留已有输入，避免覆盖用户后来输入的文字。
- 补充附件名称和 MIME 类型回退，限制外部 Intent 的 URI 扫描数量；导航不接受调用者提供的文件路径。

## 沿用与去重

- BOM 文档读取修复已在 r20，本次没有再次引入旧版本实现。
- 生图、GIF/MP4 导出、共读、技能缓存、自动标题与子代理 `reasoning_content` 修复全部沿用 r20，没有重新调用付费 API 探测。
- 图片仍只整理用户选择的来源，不自动删除原图；系统权限仍需用户授权。

- 复用生产力分支刚完成的 **27/27 项 Kotlin/JUnit 定向测试**、后台整理/共同阅读 **2 组接线编译**，没有重跑全量测试。
