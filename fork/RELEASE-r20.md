# RikkaHub 3.1.1-r20 · 后台整理、共读与媒体导出

基于正式 r19（`043bc398`）累加，版本 `3.1.1-r20 / 3000067`，原包名、签名、应用名、图标、六只角色原图与完整人设不变。旧标签和资产保留；升级本分支无需卸载，升级前请备份数据。

## 子代理思考字段修复

修复非流式回复解析把正文放在工具之后，导致续轮时拆出额外 assistant 消息、缺少 `reasoning_content` 的问题。子代理默认非流式，比通常走流式的主对话更容易触发这个错误。

正文与工具调用现在属于同一条 assistant wire 消息，工具边界前的多段思考完整保留。「不发送历史思考」不再删除活动工具链的协议状态；识别到 DeepSeek 且携带工具时遵守其历史回传要求。不靠关闭思考或切换模型绕过，不重放已执行工具。20 项定向检查通过，其中真实非流式 agent 循环在严格模拟上游下连续完成两轮工具和最终回复；这不代替安装后的同渠道实测。

## 图片整理在后台继续

入口「设置 → 图片整理 → 后台整理与 AI 规划」。识别任务交给 WorkManager 与前台通知，离开页面不取消；可以从通知停止。完成项逐张保存，进程被系统中断后可显式继续剩余项，结果不确定的已发请求不会静默重发。

可主动开启自动增量整理，选择聊天上传、旧生成图片或媒体创作来源。系统约每 15 分钟调度，网络与低电量条件、厂商省电和强行停止都可能延迟任务；每批最多 20 张，不扫描整个手机相册，不自动移动、重命名或删除原图。识别仍会外发缩略图并产生模型用量，默认关闭。原 1–16 路并发、模型共享上限和手动保留/删除能力不变。

「AI 规划分类」把最多 200 张已识别图片的名称、分类与描述交给所选模型，生成虚拟分组；可改组名、按组查看，方案本地保存。不存在或重复的图片 ID 会过滤。这一步只发文字描述，不再上传原图，但会产生模型费用。

## 生图参数与真实格式

入口「媒体创作」。图片支持 PNG、JPEG、WebP 与渠道原生 GIF 参数，高质量作为未选质量时的默认值。新草稿未选模型、且已经配置 o10 的 `gpt-image-2.6` 时优先使用它；不覆盖已有选择，不把私人账号或密钥写入 APK，也不会失败后偷偷换渠道。

本轮渠道对照推荐 `https://o10.top/v1` 的 `gpt-image-2.6`：实测返回 PNG 原图，横图 1536×1024、竖图 1024×1536 精确跟随；方图请求 1024×1024 实际常返回 1254×1254，结果显示真实尺寸。pure 的 2.6 实测返回 JPEG 并重采样到 1024×1024，作为用户可选备用，不宣称两条渠道字节一致。请求尺寸、输出尺寸分开，不拉伸图片冒充接口原尺寸。

o10 原生 GIF 探针确实取得 9 个不同帧、2250 毫秒的 GIF。仅选择适配模型/渠道才开放原生 GIF，实际文件仍需验证为多帧；渠道随时可能改变能力。SVG 请求实测返回 PNG，因此不把 SVG 列为已验证生成能力。`xhigh/max` 未验证，不冒充已支持。

下载结果会检查真实文件签名、解码、宽高以及动画/视频信息；空数组、空 base64、HTML/JSON 错误、坏文件不算成功。原始字节保留，按真实格式/MIME 命名，不把 JPEG 改后缀伪装 PNG。

## 本地导出与动效

图片结果菜单「本地导出」可真正编码 PNG、JPEG、WebP；尺寸可改，可选择完整容纳或居中裁切，不直接拉伸原图。另可把已有图片导出为多帧 GIF 或 H.264 MP4，选择缩放、平移、淡入和 2–5 秒时长，完成后可保存到相册或分享。

这是本地图像运动，不是 AI 生成新的视频场景。原图不修改；取消会清理未完成文件。动效最大约 1920×1080 像素面积，MP4 宽高必须是偶数，设备还需有支持该尺寸的编码器；没有编码器时明确失败，不用假视频替代。GIF/WebP 输入按首帧制作。淡入 GIF 按帧学习色板，避免空白首帧让整段动画失色。

## Responses 文件输出

解析带有效 `container_id/file_id` 的 Responses 文件引用，按当前提供商的鉴权端点取回并落地；下载有界、不跟随重定向、不向其他域名泄漏密钥。取不到时标记失败，未落地引用不会作为真实附件发回模型。

pure 的本轮探针只给出 `sandbox:/mnt/data/boat.gif` 文本，没有可用文件 ID，不能算生成成功。因此本版不承诺 pure Responses GIF 已可用；真正可用的已测 GIF 路线是上面的 o10 原生输出。模型只写一个下载链接，客户端不会凭空变出文件。

## 网页共读与更多文档

入口「设置 → 权限与软件关联 → 网页共同阅读」。启用后，主动发送的 http(s) 链接可提取正文，连同用户问题一起交给 AI；后续对话复用当前助手与原消息的阅读缓存。不会后台爬取历史里尚未读取的链接，压缩请求也不额外访问网络。每条最多 3 个链接，有超时、大小、重定向与公网地址检查；失败或截断明说，网页文本作为不可信资料而非系统指令。

附件阅读补充 XLSX、ODT/ODS/ODP、HTML 以及常见文本、代码、CSV/TSV、JSONL、YAML 等格式，保留 PDF、DOCX、PPTX、EPUB 路线。Office/表格提取文字和坐标，不还原完整排版、不执行宏或公式、不解 DRM；正文和压缩条目有上限。需登录、强脚本渲染的网页未必能读取，可用原系统 WebView 预览。

## 技能、提示词与标题

技能元数据只读头部，正文按需读取；统一有界文件缓存，App 编辑/删除/导入后失效，并检查磁盘变化。缓存不保存跨助手启用状态，不用缓存命中冒充模型已读过技能，也不替换当前助手人格。提示词来源和顺序更稳定，正则复用编译结果；「设置 → 高级与长任务」可查看实际系统提示词组成与字符数。没有真实供应商缓存命中率的承诺。

用户消息可靠保存后立即后台按已配置规则起标题，不等 AI 回答结束，也不阻塞聊天；一轮完成后按新内容兜底或精修。用户手改优先，晚到的自动标题和手动重生成请求都不能覆盖后来的手改；切分支不带旧分支的自动标题进度。标题状态不增加数据库列，重启后已有标题保守保留。

## 权限与软件关联

集中查看通知、摄像头、麦克风、悬浮窗、后台电池与所有文件访问状态；只在用户点击时进入 Android 授权/系统设置，声明权限不等于获得权限。保留已有工作区 Shizuku/Root 入口，不绕过系统。

系统分享可接收文字、网址与多个文件；支持内容 URI 文档「用此应用打开」及选中文字处理。入口先由用户选择对话/发送，不自动发给模型；生成物可保存、分享。不抢占浏览器 http(s) 默认打开，也不接受其他应用借自身 provider URI 读取私有文件。

## 验证范围

本轮只做改动相关的真实 Kotlin/JUnit 检查及正式 Windows `release` 构建（R8 + lintVital），不跑历史全量测试。最终冻结提交、构建 sourceId、测试数量、APK 版本/签名/ABI/资源、源码与公开下载哈希，以同一 Release 的机器可读回执为准。

未自动安装手机，未完成真机界面、系统后台调度、设备 MediaCodec 导出与同子代理供应商的安装后验收。独立 GIF 解码及纯逻辑检查不能替代这些设备验证。Android 强杀仍可中断后台任务，网络与上游收费行为不由客户端保证。
