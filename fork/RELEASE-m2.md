# RikkaHub · Meridian 3.1.1-m2

> **增量版本。** m2 建在 m1 之上：m1 的完整能力原样保留，本轮只加手动对话归组、同模型渠道优先级、单对话思考强度三项。
> 直接用 `rikkahub-3.1.1-m2.apk` 覆盖 m1（或 r21 及更早的本分支版本）即可，不需要先卸载，也没有「先装哪个包」的问题。
> m1、r21 的 Release / tag / 资产原样保留（回滚与历史对照用）。

## 本轮新增三项

| 功能 | 入口 | 默认 | 边界 |
|---|---|---|---|
| 手动对话归组 | 会话抽屉 → 长按一条会话 → 多选 → 加入现有分组或新建分组 | 不使用时不改变列表 | **不是把多条会话合成一条**：组内仍是独立会话，各自的消息、上下文、思考与用量都不变，可单独打开；组头可展开/收起、改名、查看全部、解散，解散只把成员移出组、不删消息；成员查询按助手隔离；手动入组会锁定自动归档分配，避免下一轮被自动搬走；展开状态按助手记住；复用已有文件夹归属，无数据库迁移；组内联显示 60 条，其余走「查看全部」分页 |
| 同模型多渠道优先级与故障切换 | 设置 → 模型与服务 →「渠道优先级与故障切换」 | 关闭 | 只在**同一 `modelId`** 的显式白名单内调用，顺序完全等于你排的顺序（当前会话渠道不会被悄悄插到第一位）；只在**同一协议族**内切换，跨协议（OpenAI 兼容 / Claude / Google / 网页登录）不互换；已输出正文、思考、工具调用草稿后**不换渠道重发**，交给已有的检查点恢复；用户取消、请求格式错误、整体断网不切换；白名单全部失效时明确报错，不回退到列表外渠道；每次切换等于用另一个提供商凭据重新请求，**可能额外计费**，用量记在实际出话的渠道 |
| 单对话思考强度 | 聊天输入栏上方的思考档位 | 新对话：模型声明 REASONING 默认 **MAX**，未声明默认 AUTO（不强加参数） | 只落当前对话，不写回助手；旧会话已保存的显式档位原样保留；首条消息发出前的选择也会存进草稿（只改档位也会写盘，光标移动不会）；助手设置页不再提供全局思考强度项；MAX 仍按各提供商原有映射发送，**未实测真实服务端是否接受最高档** |

## 同时收尾的两项 m1 P1（未完成，不计入已验证）

- **MCP 幂等账本**：区分「首次不存在」与「已存在但损坏/不可读」，后者保留坏文件、冻结写入并返回明确不可用，不再把坏账本当空账本重新授权同一个 key；落盘改为临时文件 + fsync + 原子替换，替换失败拒绝执行，不再截断覆盖正式账本。
- **自动化步骤**：写盘结果上抛，RUNNING 标记没落盘就**禁止 dispatch** 写步骤；运行账本读坏时禁用写配方并要求人工核对实际状态，不再当空账本继续跑。

两项都在**本轮修复中**，还没完成构建与窄验证，因此本文件与首页都不写「已修复 / 已验证」；最终构建与安全验证结论随后补记。普通文本聊天不受这两项影响，但在这之前不要把设备写与自动化路径当成可无人值守可靠使用。

## 不要误读的地方

- 分组不合并消息、不改 lineage 与上下文；它不是「把几个对话变成一个」。
- 渠道切换只管主聊天的模型请求，模型必须在各提供商里写法一致（`modelId` 相同）才会被当成同一个模型；设置页文案目前只有中文，英文界面会看到中文说明。
- 单对话思考档位不改变助手默认，也不保证服务端接受最高档；升级不会改写旧会话的显式选择。
- 115 项是纯策略与 Fake 层的检查，不覆盖 Compose 真实点击、Room Flow 刷新、文件系统突然损坏、网络竞态与服务端参数接受度；通过检查不等于异常恢复一定正确（见上面两项 P1）。
