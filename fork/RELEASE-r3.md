# RikkaHub 3.1.1-r3

本版修复切换 Wi-Fi、移动网络或 VPN 后的连接恢复。版本 `3.1.1-r3 / 3000050`，包名、正式签名与数据库 schema34 不变，保留 r2 的每模型设置与之前的工具调用增强。

## 网络切换

- 监听 Android 默认网络，不绑定指定出口，不绕过 VPN，也不要求 Google 网络验证通过才允许使用。
- 文本生成在旧网络连接失效时退出旧请求，把错误交给原有重试策略；网络恢复后等待约750ms稳定期即可重试，不必等完原来30/60秒退避。未发生切网时仍按用户原设置等待，关闭自动重试或设为0仍不重试。
- 等网络恢复时不占每模型API名额，用户点击停止会取消等待与请求，不会被后续网络事件重新拉起。
- 重试时先保留已显示的回复；新内容追上并延续旧文本才更新预览。如果模型重生成了不同答案，成功后整体替换，不硬拼两次结果、不重复执行已经完成的工具。
- OpenAI Chat Completions/Responses、Claude、Gemini/Interactions 未收到协议结束信号就关闭的流，不再伪装成正常完成；明确的结束原因和合法usage尾帧继续兼容。

## MCP 恢复

- 网络恢复会重新初始化受影响的远端MCP会话。健康的localhost服务不因VPN切换而被强制重连。
- 首次连接失败、连接断开和SSE内部重试耗尽都会进入统一恢复；每个服务只保留一个重连任务，旧连接不会继续被当成健康连接。
- 离线时不空转消耗预算。连续失败最多5次，之后等待网络恢复或下次调用，不增加永久巡检定时器。需要OAuth授权的服务不自动循环登录。
- 初始化和工具目录同步有20秒上限，旧连接关闭有3秒上限，避免卡着锁阻塞后续恢复。
- 工具调用已发出但结果丢失时，明确返回“执行结果不确定”；客户端不自动重放，也关闭MCP HTTP层的自动连接重试，防止重复写入。

## 边界

VPN更换出口后，旧TCP连接不能原地迁移。这里实现的是客户端检测、保留界面内容和重建请求/会话，不能承诺零延迟或模型逐字接着同一次生成。重发模型请求可能再次计费。

用户手机和实际机场服务仍需安装后验证；本版不修改机场配置，不绕过其路由，不声称恢复已断的SSH终端或远端前台进程。执行结果未知的工具操作必须先检查服务端状态，不能因为恢复了连接就当成未执行。
