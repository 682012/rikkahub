# 3.1.1-fork.42：Agent 工具架构重做

版本 `3.1.1-fork.42 / 3000046`，包名 `me.rerere.rikkahub.fork`，数据库仍为 schema 34。基于 fork.41，保留 PRoot 整棵进程树停止修复与官方 master `5ad19405` 的多关键词模型筛选。fork.41 和所有旧 Release 不覆盖。

## 改了什么

- **真并发**：相邻独立读取最多 8 路，写入和未知工具是顺序屏障。相同原生读取只在同批合并，不用跨轮缓存冒充新结果。
- **少往返**：`tool_batch` 一次安排最多 16 个已明确参数的操作，保留内层审批和输出顺序。有依赖的操作不盲目并发。
- **工具定义按需取**：MCP 达到 16 个工具或定义体积达到 20K 字符时，只携带 `tool_search` / `tool_call` 两个稳定入口；搜索命中才返回 schema。小目录保持原生。
- **结果可读回来**：超过 16K 字符保留全文，首屏头尾约 4K，`tool_output_read` 分页恢复。HTTP/SSH/无工作区同样可用，图片等非文本附件保留，写盘失败不丢原结果。
- **子代理不反复塞正文**：终态发小通知；一次等待最多 8 个任务，共用期限和首屏预算。原子首屏交付，重复 wait 只回状态和读取提示；结果分页重读与重启恢复。
- **修真 bug**：流式/非流式重复或空工具 ID 隔离；未知副作用调用中断后不自动重放；工具开始和结果即时落库；App 启动不再清空历史输出目录。
- **少做无效工作**：连续不变的原生读取提醒模型换方法，不封必要验证；工具/技能目录排序稳定，只有文本中实际出现的占位符才求值；工具错误不回填整段堆栈。

子代理默认并发 4、上限 8；已保存的值不强改，开关仍按用户设置，模型 allowlist 和上下文隔离不放宽。

[完整架构、协议边界与代价](AGENT-ARCHITECTURE.md)。参考了 Codex 的显式并发能力和写屏障、Pi 的批量执行与结果交付、Cloudflare 的紧凑工具发现；没有把 Workers 沙箱或 Anthropic 私有 tool_reference 伪装成全模型通用功能。

## 已跑的对照

固定模拟 MCP 目录、虚拟时钟和 fake provider 的可复用测试，不是营销百分比。

| 场景 | 旧路径 | 新路径 |
|---|---:|---:|
| 120 个模拟 MCP 工具，携带定义字符数 | 72,264 | 1,910（降低 97.36%） |
| 4 个参数已知的独立读取，虚拟执行耗时 | 1,000ms | 250ms |
| 上述读取加最终回复，fake provider 请求数 | 5 | 2 |
| 40,000 字符工具输出，首次回填 | 40,000 | 4,741，全文仍在 |

**量的是定义字符数、真实循环的模拟请求数和调度耗时，不能据此宣称实际账单 token 降 97%、上游缓存命中率提高或联网延迟快四倍。** 模型是否主动合并独立调用也需要实际会话观察。`AgentEfficiencyBenchmarkTest` 随源码保留，可重新跑。

## 保留的代价

全文持久化会占磁盘，当前不无条件清理历史结果；超大文件分页面向按需读取，不建议机械把全文一页页灌回模型。未知工具仍串行，批量入口也不能替代真正的依赖编排。新框架不能消除模型自行发起的每一次无价值读取，但会减少重复执行、无效回填和不必要往返。
