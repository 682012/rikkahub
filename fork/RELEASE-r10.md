# RikkaHub 3.1.1-r10

r9 的后续版本，版本码 3000057；包名、签名、官方名称与图标、数据库结构保持不变。当前文件先记录实现；构建与验收数字以最终 `verification/r10.json` 为准。

## 沉浸聊天

有壁纸时默认去掉包住整条消息的厚重大圆角外框，正文、顶部与输入区各自保留薄底。壁纸加载失败或移除后回到实色，不留下透明页面。仍有经典、工作台、专注三种布局。

入口：设置 → 偏好 → 主题 → 沉浸聊天。关掉可恢复卡片；沿用面板强度滑块，不再多加一组透明度设置。对比保护会随壁纸明暗与主题调整，花背景不等于强迫文字悬空。

用户消息仍靠语义结束边、助手靠起始边；原有长文折叠、顶部折叠、附件预览不撤回。

## 多步 tok/s

每步分别记录可信的输出 token 与生成窗口，聚合为“已测输出 token 总和 ÷ 这些步骤的生成窗口总和”。未测步骤仍计入总用量，但不混入吞吐分子。部分覆盖可显示数值，并注明已测几步/总步数；顶部与消息底部使用同一口径。

非流式、缺少 usage、单包返回、少于 200ms 的突发、服务端工具等待/内部续写不硬算；详情解释缺测原因。重试单独计时，不把失败尝试的等待混进下一次速度。

旧记录只有在 token 与窗口可以对应时才能继续用；旧的部分计时记录没有逐步 token，无法可靠补回。不会按字数估一个 tok/s，也不会把总 token 除以残缺时间。

## 图片历史的压缩

修复压缩请求把 assistant 图片原样传给 LiteLLM 等转发层而产生的 `Images in assistant messages are not supported`。

含附件的压缩范围转成带角色与工具关联标记的文本，保留图片/文件存在、来源、文件名及已有描述，结构化图片字节不再作为 assistant 图像块上行。原聊天、原图和附件引用保持不动。不会为了这次压缩偷偷再发 OCR 请求。

纯文本历史沿用原来的请求角色结构与缓存前缀。压缩适配层不额外截掉普通正文、工具输出、既有摘要或最早需求；已有的压缩范围和输入转换配置照常工作。

## 小助手 AI 与运行状态

不必逐条写点击台词。选择已有模型，或启用跟随当前会话后，由模型根据点击、自己的近期互动及任务事件生成短回应。三张透明立绘原图不变，不引入 Live2D、Node、Electron 或额外服务。

入口：设置 → 偏好 → 通知 → 悬浮角色 → AI 互动；后台悬浮角色展开后可查看“小助手 AI”详情、输入一句话、查看近期互动、停止或再次生成。模型未配置会明确显示，不暗换到其他已配置模型。

状态来自实际请求与流式数据：空闲、等待/生成、完成、失败、取消；可查看模型、触发事件与错误。停止和关窗立即取消，迟到结果不能把取消改成完成或写入小助手记忆。状态卡与任务预览共用受限滚动区，主聊天回复/停止入口留在面板内。

自动互动默认关闭，打开后按事件触发并去重、限频、限制一次在途与超时；不设定时轮询。请求记为独立 `COMPANION` 用量，复用现有模型并发限制。不把主聊天全文、标题、系统记忆或密钥放进小助手提示词。每次模型调用仍可能产生供应商费用。

这次的小助手是对话与任务状态陪伴层，不是一个另起工具执行循环、擅自操作设备的后台 Agent。
