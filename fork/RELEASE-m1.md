## 为什么只有一个包（r21 / r22 的疑问）

- **r21** 是已发布版本（`v3.1.1-r21` / `3000068`），Release、tag 与资产都保留作历史与回滚材料；降级需先备份并考虑数据库版本差异。
- **r22** 是开发期的本地回滚基线，保留源码和已验签的本地回滚包，但**没有单独发过 Release**。
- **m1** 在这条基线上把 r21 的已发布改动、r22 阶段改动和本轮七项功能合成一个运行时，所以版本号从 r21 直接跳到 m1。

因此：**不需要依次安装**，也不存在「先装哪个包」的问题。同包名同签名，r21 及更早版本可被 m1 直接覆盖；升级前照常备份聊天与设置，不要为了升级先卸载。

## 本轮新增（七项，都有入口和默认值）

入口大多在**聊天输入栏上方的「会话选项」**，配置按会话保存。

| 功能 | 入口 / 选项 | 默认 | 费用与边界 |
|---|---|---|---|
| AI 输入优化 | 会话选项 → 输入优化 | 关闭 | 开启后可能额外发起模型请求，**单独计费**（缓存命中或不适用的输入不额外调用）；原文照常显示与保存，只改发给模型的副本，可切换查看原文/优化版；优化失败或取消仍用原话继续 |
| 回复审查 | 会话选项 → 回复审查：关闭 / 同模型自检 / 独立审查 | 关闭 | 同模型自检不另发请求；独立审查**另发请求并单独计费**。审查意见只是模型意见，不能当作代码已编译、运行或验证 |
| 客户端协议兼容档 | 会话选项 → 协议：原生 / 自动 / Codex / Claude Code / Pi | 原生 | 影响提示与工具用法及兼容请求头；自动选择**不发探测请求**，一轮内稳定。不伪造账号凭证、不获得官方客户端权限、不绕过服务验证 |
| 运行中插话 | 会话选项 → 运行中消息：排队 / 安全下一步插入 | 排队 | 不打断已发出的请求，不重放正在跑的工具；审批中、带附件、不满足长度条件时继续排队 |
| 本地知识库 | 会话选项 → 本地知识库 → 管理资料（粘贴/文件导入、检索、查看、编辑、删除） | 关闭 | 按助手隔离，引用保留来源；开启后命中的片段随当轮请求发给当前对话模型（**增加该轮 token 与费用**，不单独计费）；不全量注入 |
| 工具执行短指引 | 会话选项 → 高效执行，随当前真实工具生成 | 默认开启，可关闭 | 只影响给模型的工具使用说明，不裁剪工具、不改变权限；只读调用仍可并行 |
| 高级权限与设备能力 | 设置 → 权限中心 → 高级权限与设备能力 | 关闭 | 见下节；需要用户自己授权 |

### 高权限中心说的是什么权限

- 可管理 **Shizuku**、`WRITE_SECURE_SETTINGS` / `DUMP` / `READ_LOGS` / `CHANGE_CONFIGURATION` 四项开发权限、系统特殊访问页面、绑定助手与独立写开关，并按**真实回读**显示授予/撤销结果。
- 六个 `android_*` 工具接入聊天、本机 MCP 和本地自动化；自动化下拉只列授权范围内的工具。
- 写操作（`settings_put` / `shell`）要独立写开关 + 幂等 key，同一 key 换工具会被拒绝；未知副作用不重放，敏感操作串行。
- **这不是 root**：拿不到系统签名专属权限，不能读其他 App 私有数据、不能截取 secure 屏幕、不能绕过 SELinux。开发权限只能由你自己用 ADB/Shizuku 授予，装 APK 不会自动获得；OEM 是否放行 `pm grant` 要看本机实际结果。

## 启动动画

- 默认 **RING**：三瓣（3 个轨道瓣）流线互相咬合，**280ms**，基准半径 **40dp**，瓣描边 **1.7dp**，中心一点亮芯；只在冷启动进桌面时播放一次，系统关闭动画时跳过。
- 可选 **DOTS**（光点聚合）与 **AURORA**（柔光散开），也可关闭或使用自定义素材。
- 入口：设置 → 偏好设置 → 主题 → 启动动效。本轮未改动动画源码，RING 仍是已审看的默认样式。

## 一并带上的修复

- 修复加载占位与会话回收期间聊天记录短暂变空的窗口；内容未就绪时不会把草稿或消息记到错误助手。
- 输入优化加代次守卫：删除、迁移、关闭或新轮次之后，迟到的优化结果不会复活；作废代次不永久占位。
- 重新生成旧回复时，知识库只检索实际发送的历史；辅助请求期间改动的会话选项在创建轮次前重新取值。
- 输入辅助意外异常回退原话，外层取消仍正常上抛；不把取消伪装成读取或导入失败。
- 插话长度计入多段文字之间的换行；坏 metadata 不崩溃；重启去重同时核对队列 ID、来源与完整原文；落库失败不确认、不吞输入。
- 权限门禁单点化：权限中心显示与实际执行走同一个控制器；撤销后能正确显示 `granted=false`；授权开关保存串行，避免迟到保存把已关的开关重新打开。
- 修复设备密码输入类型的判定，普通网页输入不再被误认成密码。
- 修正旧压缩测试里错误的 42/21 断言（原断言写成 44/22），生产压缩实现未因此改动。
