# RikkaHub 3.1.1-r2

版本 `3.1.1-r2 / 3000049`，包名、签名身份和数据库 schema 34 不变。沿用上游 RikkaHub 名称及兔子图标，保留 r1 / fork.43 的全部增强功能。

## 每个模型自己的运行设置

入口：**设置 → 提供商 → 选择提供商 → 编辑模型 → 基本**。

- **上下文大小**：继续使用已有的 128K / 200K / 1M 预设或自定义正整数，单位为 token。它是客户端上下文占用与压缩判断的依据，不会改变上游 API 的实际容量，也不等于输出 token 上限。
- **自动压缩**：可以跟随全局、单独开启或单独关闭。模型开关优先于全局：全局关闭时仍能为单个模型开启，反之亦然。
- **压缩阈值**：10%–100%，留空沿用全局阈值。按该模型的上下文大小计算触发点；摘要仍由全局指定的压缩模型生成，未指定则跟随对话模型。保留原始历史，不压缩尚待执行/审批的工具调用。
- **最大并发请求数**：1–64，留空不额外限制。同一模型配置的聊天、子代理、摘要等 API 请求共享名额，超过上限可取消地排队；不同模型配置互不占名额。

配置按模型的稳定 ID 保存，同名但不同提供商/不同配置条目的模型可以设不同值。旧模型与旧备份缺少新字段时，继续沿用原行为。上下文、自动压缩开关、阈值、并发分别独立，不会因重置其中一项而清掉其他设置。

## 并发边界

- 这是 **API 在途请求上限**，不是重复请求次数、工具并行数量或子代理总任务数。全局子代理并发与设备内存限制继续生效，模型设置不能越过它们。
- 请求结束、失败或取消后释放名额。重试等待和工具执行阶段不占 API 名额，避免父任务等待同模型子代理时互锁。排队使用稳定的先来先服务顺序，正在连发请求的任务不能插到已有等待者前面。
- 修改上限不取消已在途请求；降低后等待在途数量回落，提高后放行排队请求。旧会话持有的模型快照也使用最新保存的上限。
- 自动压缩继续用于聊天会话的既有安全发送点；本版没有另改子代理循环的摘要机制。

## 输入与保存

空白、非法字符、零、越界或整数溢出都在表单检查。无效的数字草稿不能确认保存，不把负号删掉再悄悄存成正数。取消编辑不写入设置；恢复默认以 `null` 保存继承关系。
