# 3.1.1-fork.38 更新说明

基于官方 **RikkaHub 3.1.1 / `ad2c4430`**；本分支版本 **`3.1.1-fork.38 / 3000042`**，包名 `me.rerere.rikkahub.fork`，数据库保持 schema 34。

这次统一了两轮 fork.37 审查成果，并补齐重试等待设置与工作区 ZIP 导入。第二轮最终源码已经包含第一轮封存修复，没有再次叠加同一份补丁。

## 用户能看到的变化

### 重试等待真正可配
- 固定 30 秒、固定 60 秒。
- 每次在 30–60 秒之间随机取整秒，也可自定义 1–600 秒范围。
- 最大重试次数仍可设 0–100，关闭或 0 次不重试；主对话与子代理共用配置。
- 修复在 30–60 预设下点“自定义”无效、输入到预设值时编辑器消失的问题。
- **新默认是固定 60 秒。** 旧版实际为 1/2/4 秒指数退避、上限 60 秒；升级后等待方式有变化。

### ZIP 导入为新工作区
- 工作区列表与高级设置都能选择 ZIP，创建独立本地工作区，不覆盖原文件、聊天或会话绑定。
- 支持旧裸 ZIP、Unicode 名称与内容、空目录、有效空包、二进制、大小写不同的文件名。
- 可明确去掉 `workspace/` 或 `files/` 外层目录，不猜测包结构。
- 导出可选择是否跳过缓存/构建目录，完成页显示实际跳过数量与示例。
- 导入先验证再发布；取消恰好发生在提交时，以真实提交回执显示结果，不删掉已注册文件。

## 修复与加固
- ZIP 路径越界、重复/文件目录冲突、CRC 与实际大小、ZIP64 65535 边界、目录伪装 payload 等整体校验。
- ZIP 内的 0600/0700 普通文件权限原样保留，不扩大为 0644/0755；不恢复 setuid/setgid。
- 过期导入 staging 按需回收，活跃导入跳过，不跟随符号链接；没有新增后台清理定时器。
- HTTP/SSH 的 job 列表不误读本机任务；不虚构尚不存在的 HTTP list 接口。
- 进度通知精确清理，5 分钟无更新过期；不停止生成任务或前台服务，不加无限续期心跳。
- **真实 Android 补漏**：requery 原生小窗口可能报 `Couldn't read row N column M`。仅在精确文本和 `CursorWindow.nativeGet*` 堆栈同时匹配时转为完整分片回退；其他错误和分片失败继续抛出，不返回半截会话。

## 明确没有做的事

- 用户手机生产库升级、厂商通知、锁屏保活与所有 SAF 提供商未验；Android 结果来自隔离模拟器。
- ZIP 只迁移文件区，不含 Linux Rootfs、App 数据库或整机。不恢复符号链接；旧包缺少的权限信息无法凭空恢复。
- 默认 ZIP 上限 100000 条目、12 GiB 展开、4 GiB 单文件/ZIP；分卷、加密和非 UTF-8 文件名明确拒绝。
- 超大历史的 UI 懒分页、远程服务重启前任务的安全接管没有实现。
- 未修改审批边界，未自动安装用户手机，未部署或重启生产远程服务。

## 为什么功能数写成“5 + 2”？

相对官方 3.1.1，按用途统计 **5 组新增工作流**，另列 **2 项主要功能增强**；修复不计新增。单会话用量面板是官方统计能力的增强，ZIP 导入/导出是一组迁移流程。详见 [完整官方差异表](FEATURES.md)，不把计数变化误解为功能减少。
